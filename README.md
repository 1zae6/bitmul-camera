# 빗물받이 촬영기

빗물받이 사진을 폰으로 찍어 모으고(목표 200장, 그중 두 사람 등급이 같은 정답지 100장 이상), PC에서 보고 등급을 매기는 팀용 도구다.

- **폰 촬영 앱(PWA):** `https://1zae6.github.io/bitmul-camera/`
- **PC 뷰어:** `https://1zae6.github.io/bitmul-camera/viewer.html`

## 하는 일

| 화면 | 기능 |
|---|---|
| 폰 촬영 앱 | 흰 틀에 빗물받이를 맞추고 멈추면 자동 촬영(흔들림·각도·선명도 검사), 수동 셔터, 빨간 박스 조정, 찍은 사람의 1차 등급·신고 필요 입력, 빗물받이 번호·청소 전/후·메모 입력, 위치·시각 자동 기록, 저장 직후 AI 채점 결과 확인, 인터넷이 끊기면 폰에 보관했다가 다시 올리기 |
| PC 뷰어 | 사진 목록·필터, 지도, 사진 정보 고치기·연습용 표시·삭제·원본 내려받기, 등급·신고 필요 매기기(다른 사람 등급과 번호·단계는 가림), 두 사람 일치율·코언 카파, 정답지 CSV, AI 채점과 사람 정답 비교 |

로그인은 팀 공용 비밀번호 하나로 하고, 이름으로 촬영자·채점자를 구분한다.

## 처음 설정 (한 번만)

1. **Supabase 키:** `.env.example` 을 복사해 `.env` 를 만들고 값을 채운다.
   - `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`: Supabase → Project Settings → API Keys
   - anon(public) 또는 Publishable 키만 쓴다. service_role / secret 키는 넣지 않는다.
2. **데이터베이스:** Supabase → SQL Editor 에 `supabase/schema.sql` 전체를 붙여 넣고 Run.
3. **팀 공용 계정:** Supabase → Authentication → Users → Add user → Create new user
   - 이메일은 팀이 정한 주소(이 주소는 앱 코드에 들어가 공개된다), 비밀번호는 팀 비밀번호
   - **Auto Confirm User** 를 켠다
   - 만든 이메일을 `.env` 의 `VITE_TEAM_EMAIL` 에 넣는다
4. **회원가입 막기(중요):** Supabase → Authentication → Sign In / Providers → **Allow new users to sign up** 을 끈다.
   켜 두면 누구나 계정을 만들어 사진을 볼 수 있다.

## 실행과 배포

```bash
npm install
npm run dev        # http://localhost:5180 (촬영 앱), /viewer.html (뷰어)
npm run typecheck
npm run deploy     # 빌드한 뒤 gh-pages 브랜치로 올린다
```

배포 뒤 GitHub 저장소 → Settings → Pages 에서 Source 를 `Deploy from a branch`, 브랜치를 `gh-pages` / `(root)` 로 한 번만 정한다.

카메라가 없는 PC에서 흐름을 시험하려면 주소 끝에 `?demo=1` 을 붙인다. 샘플 사진은 연습용으로 저장된다.

## 등급 기준 (v4)

빨간 박스 = 빗물받이 덮개, 흰 점선 = 박스를 사방으로 20%씩 넓힌 주변. 덮개와 주변을 따로 보고 **둘 중 더 심한 쪽**으로 매긴다.

- 덮개: 빨간 박스 안을 쓰레기가 위에서 가린 비율
- 주변: 빨간 박스 밖, 흰 점선 안을 쓰레기가 덮은 비율

| 등급 | 더 심한 쪽이 덮인 비율 |
|---|---|
| 0 깨끗함 | 5% 미만 (덮개·주변 둘 다) |
| 1 조금 쌓임 | 5~25% |
| 2 꽤 쌓임 | 25~50% |
| 3 많이 막힘 | 50% 이상 (덮개가 다 막힌 것 포함) |
| X 판단 불가 | 빗물받이가 아니거나 흐리거나 너무 멀어서 알 수 없음 |

- 쓰레기·낙엽·흙·담배꽁초를 모두 센다. 덮개 위에 덮어 둔 고무판·장판·비닐도 쓰레기로 센다.
- **신고 필요**(등급과 별개): 빗물받이 아래(덮개 틈 안쪽)에 쌓인 쓰레기. 시민이 덮개를 열고 치울 수 없으므로 등급에 넣지 않고 따로 표시하고, 지자체가 나중에 신고된 곳을 청소한다.
- 사진에 보이는 것만 보고 매기며, 애매하면 높은 등급을 고른다.
- 기준 문장은 `src/shared/grades.ts`, 주변 범위는 `src/shared/config.ts` 의 `contextPadding` 에 있다. 사람 화면과 AI 지시문이 같은 문장을 쓴다.
  기준을 바꾸면 `src/shared/ai.ts` 의 `PROMPT_VERSION` 을 올린다. 정답지 등급을 매기기 시작한 뒤에는 바꾸지 않는다.

## AI 채점 (Gemini)

Gemini 키는 Supabase 서버 함수 `grade-photo` 에만 두고, 폰과 PC 뷰어는 로그인한 상태로 이 함수를 부른다. 키는 폰·PC·GitHub 어디에도 들어가지 않는다.

**서버 함수 만들기 (한 번만)**

1. Google AI Studio(https://aistudio.google.com/app/apikey)에서 API 키를 만든다.
2. Supabase → Edge Functions → Deploy a new function → Via Editor 에서 함수 이름을 **`grade-photo`** 로 바꾸고,
   `supabase/functions/grade-photo/index.ts` 내용을 통째로 붙여 넣은 뒤 Deploy function.
3. Edge Functions → Secrets 에 `GEMINI_API_KEY` 로 키를 넣는다.
4. 모델 목록을 바꾸면 함수의 `MODELS` 와 `src/shared/config.ts` 의 `ai.models` 를 같이 고친다.

**폰: 찍고 바로 채점.** 찍은 사람이 저장할 때 1차 등급과 신고 필요를 고르면, 저장 직후 AI 결과가 나란히 나온다
(등급·신고 판단이 같은지, 덮개·주변 비율, 확신도, 원인, 이유). 결과는 `현장 즉시 채점 · 모델 · 기준 v4` 실행 하나에 계속 쌓인다.
홈 화면에서 끌 수 있고, 2차 등급은 다른 사람이 PC 뷰어에서 매긴다.
PC 등급 화면은 기본으로 '아직 한 명만 매긴 사진'만 보여 줘서 사진마다 2명(찍은 사람 + 1명)만 매긴다. 정답지는 매긴 사람 전원이 같은 등급이어야 들어가기 때문이다.
폰 저장 화면은 항상 '다음 번호 · 청소 전'을 먼저 채운다. 같은 빗물받이의 청소 후·재방문은 번호와 단계를 직접 고른다.

**PC 뷰어: AI 채점 탭.**

1. 모델, 방식(기준 문장만 / 등급별 예시 사진 1장씩), 대상(정답지 사진 등), 최대 장수, 요청 간격을 고르고 **AI 채점 시작**.
2. 하루 한도가 작은 모델은 최대 장수를 한도에 맞춰 두고, 다음 날 결과에서 **이어서 채점**을 누르면 같은 실행에 이어서 매긴다.
3. 서버 함수 없이 시험할 때만 '고급'에서 그 PC 브라우저에 키를 넣어 직접 부른다(그 브라우저에만 저장).

- 사진 1장마다 요청 1번이다(여러 장을 한 프롬프트에 묶지 않는다).
- 결과의 **AI 답 전체** 표와 사진 상세의 **AI 답**에서 사진별 답과 JSON을 볼 수 있다.
- 보내는 사진: 흰 점선 범위만 잘라 빨간 박스를 그린 사진(긴 변 768px).
- 결과는 `ai_runs`·`ai_grades` 표에 저장되고, 두 사람 이상 같은 등급을 준 사진(정답지)과 비교해 완전 일치·±1 이내·코언 카파·등급 맞대기 표·신고 판단 일치를 보여 준다.
- 무료 한도에 걸리면 기다렸다가 다시 보낸다. 한도 숫자는 AI Studio에서 계정별로 확인한다.
- 무료 구간에 보낸 내용은 구글 제품 개선에 쓰일 수 있다. 사람 얼굴·차량 번호판이 나온 사진은 연습용으로 바꿔 뺀다.

## 조정할 값

자동 촬영 기준(선명도, 흔들림, 기울기), 가이드 틀 위치, 사진 크기는 모두 `src/shared/config.ts` 에 있다.
촬영 화면 아래 상태 표시를 누르면 실제 선명도·밝기·기울기 숫자가 보이니, 현장에서 보고 기준을 맞춘다.

## 촬영 수칙

비 올 때 촬영 금지 · 인도 쪽에서만 · 덮개 열지 않기 · 사람 얼굴과 차량 번호판이 나오지 않게 찍기.
사진은 앱에서 다시 그려 저장하므로 원본 파일의 위치 정보(EXIF)는 남지 않는다. 위치는 앱이 따로 기록한다.
